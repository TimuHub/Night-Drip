# Night Drip — Контент-пайплайн: как набирать сотни вариантов

Пошагово: как добавлять персонажей, диалоги, страницы сталкинга и модификаторы кафе без ломки архитектуры.

---

## 1. Новый персонаж

1. **Регистрация:** в `game/definitions.rpy` добавить в словари:
   - `trust["new_id"] = 0`
   - `outcome["new_id"] = "locked"`
   - `knows_about["new_id_insight"] = False` (если есть сталкинг)
2. **Расписание:** в `schedule` добавить id в нужные смены (morning/day/evening/night).
3. **Персонаж Ren'Py:** в `game/characters.rpy` — `define new_char = Character("Имя", image="new_id")`, объявить спрайты `image new_id emotion = "ch/...".
4. **Диалоги:** создать `game/dialogue/new_id.rpy` с label'ами по дням/контексту (см. ниже).
5. **Сценарий:** в `script.rpy` (или в общем label выбора клиентов) по `schedule` и дню вызывать `call dialogue_new_id_dayN` или аналог.

---

## 2. Новый вариант диалога (сотни вариантов)

- **Где:** в `game/dialogue/<character_id>.rpy`.
- **Структура одного блока:**
  - Условие: `if trust.get("sophia", 0) >= 20 and knows_about.get("sophia_art", False):` — своя ветка.
  - Реплики + `menu` с тонами (поддержать / надавить / промолчать).
  - В репликах подсвечивать ключевые слова: `{b}art{/b}`, `{b}work{/b}`.
  - В конце блока: `$ remembered_keywords.append("keyword")` или задать список слов, которые игрок может запомнить за эту смену.
- **Исходы:** при выборе «тёмного» тона — `$ nd_set_outcome("sophia", "worse")`, `nd_after_dark_choice()`, переход на бэд-энд сцену. При поддержке — `nd_set_trust`, при хорошем финале арки — `nd_set_outcome(..., "improvement")`, `nd_after_good_outcome(...)`.

Шаблон для копирования: см. `game/dialogue/sophia.rpy` и `leo.rpy`.

---

## 3. Новая страница сталкинга

1. **Данные:** в `game/stalking.rpy` в словарь `STALKING_PAGES` добавить ключ (ключевое слово) и список страниц:
   ```python
   "новое_слово": [
       {
           "id": "character_insight_id",
           "character": "character_id",
           "title": "Заголовок (сайт / ник)",
           "body": "Текст страницы (пост, переписка, новость).",
           "image": "browser/filename.png",
           "sets_flag": "knows_about key",
           "warning": "Если использовать в лоб — риск.",
       },
   ],
   ```
2. **Флаг:** в `game/definitions.rpy` в `knows_about` добавить ключ `"character_insight_id": False`.
3. **Арт:** положить картинку в `game/browser/` (или оставить заглушку — игра покажет только текст).
4. **Диалог:** в диалогах персонажа добавить ветки с `if knows_about.get("character_insight_id", False):` — новые реплики и выборы.

Масштаб: десятки слов × по 1–2 страницы на персонажа = сотни страниц при росте контента.

---

## 4. Новый модификатор кафе

1. **Флаг:** в `game/definitions.rpy` в `cafe_modifiers` добавить `"new_modifier_id": False`.
2. **Включение:** в `game/atmosphere.rpy` в `nd_after_good_outcome` / `nd_after_bad_outcome` по исходу персонажа выставлять `store.cafe_modifiers["new_modifier_id"] = True`.
3. **Визуал:** в сценах кафе использовать условие, например:
   - `if cafe_modifiers.get("poster_barista_wanted"):` — показать оверлей или переключить фон на вариант с постером.
4. **Арт:** положить слой в `game/bg/overlays/` или сделать вариант фона и вызывать его по флагу.

---

## 5. Атмосфера (напряжение, кот, дождь)

- **Подъём напряжения:** в сценарии после сталкинга уже вызывается `nd_after_stalking()`; после «тёмного» выбора — `nd_after_dark_choice()`; после плохого исхода — `nd_after_bad_outcome(char_id)`.
- **Снижение:** после хорошего исхода — `nd_after_good_outcome(char_id)`.
- **Кот:** состояние меняется в `nd_add_tension` (calm / alert / hiding). В сценах по `cat_state` показывать нужный спрайт кота или не показывать.
- **Дождь:** по `nd_rain_intensity()` выбирать интенсивность (звук/визуал) в зависимости от `tension`.

Добавление новых триггеров — вызов тех же функций в нужных label'ах.

---

## 6. Чек-лист перед релизом контента

- [ ] Все новые персонажи есть в `trust`, `outcome`, при необходимости в `knows_about` и `schedule`.
- [ ] У каждого диалога есть ветки по trust и knows_about, где нужно.
- [ ] Страницы сталкинга имеют уникальный `id`, корректный `sets_flag` и при необходимости `warning`.
- [ ] Исходы персонажей обновляют `outcome` и вызывают `nd_after_good_outcome` / `nd_after_bad_outcome`.
- [ ] Модификаторы кафе включены в нужных исходах и отражены в сценах (фон/оверлей).
- [ ] Атмосфера (напряжение, кот) обновляется в ключевых точках сценария.

Так команда может систематически набирать десятки персонажей, сотни диалогов и страниц сталкинга, не ломая общую логику игры.
