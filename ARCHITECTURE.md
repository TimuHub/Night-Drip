# Night Drip — Архитектура под масштаб

Как устроены данные и код, чтобы поддерживать **десятки персонажей, сотни диалогов, сталкинг, влияние и атмосферу**.

---

## 1. Общая схема

```
[Смена] → клиенты по расписанию (утро/день/ночь)
         → диалог с выделенными ключевыми словами
         → игрок запоминает 1–2 слова
[После смены] → браузер: ввод слова → одна «страница» (инсайт)
         → флаг «знает_X_о_Y» разблокирует новые реплики
[Следующая встреча] → ветвление по trust + «знает_X» + выбранный тон
         → исход (улучшение/нейтрал/крах) → обновление кафе + атмосферы
```

---

## 2. Персонажи (масштаб: десятки)

На каждого персонажа храним:

| Поле | Назначение |
|------|------------|
| `id` | sophia, leo, student_debt, artist, runaway, old_man, couple, influencer, … |
| `display_name` | Имя в интерфейсе |
| `trust` | Число (или диапазон: low/mid/high) |
| `romantic` | Есть ли романтическая линия |
| `arc_stage` | 0..N — этап арки (первое появление, после сталкинга, финал) |
| `outcome` | improvement / neutral / worse / locked |
| `keywords` | Слова, которые он «даёт» в диалогах (работа, долг, девушка, …) |
| `stalking_pages` | id страниц, привязанных к ключевым словам |
| `emotions` | Список эмоций для спрайтов (neutral, sad, happy, worried, …) |
| `schedule` | В какие смены может прийти (morning/day/evening/night) |
| `unlock_condition` | Условие появления (день, флаг, другой исход) |

В коде: **default-переменные в Ren'Py** (trust, outcome) + **JSON/справочник** для контента (keywords, страницы, расписание). Сценарии вызывают общие функции: `get_dialogue(character_id, context)`, `apply_outcome(character_id, choice)`.

---

## 3. Диалоги (масштаб: сотни вариантов)

Не один линейный скрипт, а **варианты по контексту**.

- **Контекст:** персонаж, день, смена, trust_band (low/mid/high), флаги «знает_X_о_Y», этап арки.
- **Вариант диалога:** список реплик + места, где игрок выбирает тон (поддержать / надавить / промолчать) + какие ключевые слова подсвечиваются для запоминания.
- **Реализация в Ren'Py:** либо ветки по `if`/флагам внутри label'ов, либо вызов `renpy.call("dialogue_" + character_id + "_" + context_hash)` из данных. Для сотен вариантов удобнее **шаблоны**: «приветствие», «ответ на тему X», «прощание» — и подстановка строк по флагам.

Структура одного «блока» диалога (для контент-редактора):

- `character_id`, `day_min`, `day_max`, `shift`, `trust_min`, `trust_max`
- `requires_knowledge`: [список флагов «знает_X» — без них этот вариант не показывается]
- `lines`: [ { speaker, text, emotion?, highlight_words? } ]
- `choices`: [ { text, tone, trust_delta, outcome_direction, next_block_id? } ]
- `keywords_offered`: [слова, которые игрок может запомнить для сталкинга]

---

## 4. Сталкинг (ключевое слово → одна страница)

- **Вход:** слово, которое игрок «запомнил» из диалога (или ввёл в браузере из списка доступных).
- **Данные:** для каждой пары (ключевое слово, персонаж) или просто по слову — одна «страница»:
  - `page_id`
  - `keyword` (или keyword + character_id)
  - `title` (заголовок «результата»)
  - `image` (путь к картинке — скрин соцсети, переписка, новость)
  - `body_text` (текст страницы)
  - `sets_flag` — флаг «знает_X_о_Y», который разблокирует реплики
  - `warning` (опционально): «если использовать это в лоб — риск потери доверия»

- **Логика:** после смены игрок открывает браузер, видит список запомненных слов (1–2 за смену). Выбирает слово → показывается страница → выставляется флаг. На следующей встрече с этим персонажем в диалоге доступны варианты с `requires_knowledge`.

---

## 5. Влияние на мир (исходы, кафе, атмосфера)

- **Исход персонажа:** improvement / neutral / worse. Записывается в `outcome[character_id]`. Влияет на:
  - финалы арки, доступ к романтике, бэд-энд (уход навсегда);
  - список модификаторов кафе (постер «ищем бариста», работа художника на стене, пустая рама, тёмные силуэты у окна).
- **Кафе:** флаги типа `poster_barista_wanted`, `artist_work_on_wall`, `empty_frame`, `silhouette_at_window`, `broken_mug`. В сценах фон собирается: базовый слой (утро/день/ночь) + оверлеи по флагам.
- **Атмосфера:** переменные `tension` (0..N), `rain_intensity`, `cat_state` (calm/alert/hiding). Музыка/амбиент и визуал (интенсивность дождя, кот) зависят от них. Повышение: сталкинг, «тёмные» выборы, плохие исходы. Понижение: честная поддержка, хорошие исходы.

---

## 6. Файловая структура (рекомендация)

```
game/
  script.rpy              # основной поток: смена, выбор клиентов, переходы
  definitions.rpy        # default: trust, outcome, flags, atmosphere
  characters.rpy         # define персонажи + изображения
  stalking.rpy           # логика браузера: доступные слова, показ страницы, set_flag
  atmosphere.rpy         # функции: set_tension, set_cafe_modifier, cat_state
  dialogue/
    sophia.rpy           # диалоги Софии по дням/контексту
    leo.rpy
    ...
  data/
    characters_registry.json   # id, keywords, schedule, emotions (справочник)
    stalking_pages.json        # page_id, keyword, character_id, image, text, sets_flag
    cafe_modifiers.json       # modifier_id, condition (outcome/flag), layer_file
  screens.rpy            # браузер, телефон, мини-игры
  gui.rpy, options.rpy
  bg/, ch/, browser/     # изображения
```

Контент (диалоги, страницы сталкинга, модификаторы кафе) можно вести в JSON/таблицах и генерировать из них .rpy или вызывать через Python в Ren'Py.

---

## 7. Контент-пайплайн (как набирать сотни)

1. **Новый персонаж:** добавить в `characters_registry.json` + создать `dialogue/<id>.rpy` с label'ами по дням/контексту; добавить спрайты в `characters.rpy`.
2. **Новый диалог-вариант:** в соответствующем `dialogue/<id>.rpy` — новая ветка или новый блок с условиями по trust/знает_X/дню.
3. **Новая страница сталкинга:** запись в `stalking_pages.json` + картинка в `browser/`; в коде браузера — подгрузка по keyword/character.
4. **Новый модификатор кафе:** запись в `cafe_modifiers.json` + арт в `bg/overlays/`; в сценах — показ по флагу исхода.
5. **Атмосфера:** вызов `set_tension`, `set_cafe_modifier`, `set_cat_state` в ключевых местах сценария (после выбора, после исхода).

Так команда может параллельно набирать десятки персонажей, сотни вариантов диалогов и страниц сталкинга без ломки архитектуры.
